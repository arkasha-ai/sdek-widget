### Auto-Resume & Persistence ✅
- **Redis-backed jobs** with 3-day TTL (migrated from in-memory)

- **Vision analysis**: Claude Haiku (3-5s) - analyzes image, finds free zones, product boundaries

- **LLM classifier** (`_classify_edit`) to determine edit type (retext vs img2img)

## Technical Decisions

### Split Architecture Rationale
- **Problem**: Haiku good at fast vision but weak layouts
- **Solution**: Haiku for image analysis + Qwen3-235B for layouts
- **Trade-off**: +15s per card for much better quality
- **Result**: Organic layouts instead of flat black rectangles

### Panel Design Philosophy
- **Legacy**: Flat black semi-transparent rectangles
- **Current**: Organic frosted glass effects that blend with scene
- **Implementation**: Specific CSS parameters + LLM constraints
- **User feedback**: Much more professional appearance

### Memory & Debug Strategy
- **Why debug logs**: Users report issues without technical details
- **Solution**: Short job IDs (#abcd1234) shown everywhere
- **Debug endpoint**: Complete pipeline traces for investigation
- **Redis persistence**: Jobs survive deployments/restarts

## Environment
- **Backend**: FastAPI + Redis + aiohttp + Playwright
- **AI Models**: fal.ai (nano-banana-pro), Claude Haiku, Qwen3-235B
- **Deployment**: Dokploy compose with webhook auto-deploy
- **Storage**: S3 (FirstVDS) for images
- **Monitoring**: Heartbeat scripts for fal.ai balance
