## Podcast Generation: Migration to Yandex API v3 gRPC

### Problem
Denis wanted better voice quality for podcast generation with more control over pitch. API v1 didn't support `pitch_shift` parameter.

### Solution
Migrated from Yandex SpeechKit API v1 (REST) to API v3 (gRPC) with full pitch_shift support.

**Installation:**
```bash
pip3 install --user --break-system-packages grpcio grpcio-tools protobuf
```

**Generated protobuf files from:**
- https://github.com/yandex-cloud/cloudapi (TTS v3 definitions)
- https://github.com/googleapis/googleapis (Google API dependencies)

### Voice Testing Process

Tested multiple configurations with different voices and settings:

**Initial tests:**
- alena, filipp, ermil, jane, madirus, zahar
- Various pitch_shift values: 0, +50, +80, +100 Hz
- Speed: 1.15x → 1.05x → 1.0x

**Research findings:**
- Optimal podcast speech rate: 150-160 WPM
- Natural male voice range: 85-180 Hz (average ~125 Hz)
- Natural female voice range: 165-255 Hz (average ~210 Hz)
- Pauses between sentences: ~300ms (natural is better than explicit)

**Tested variants:**
1. Current (Ermil +70, Alena +50, speed 1.05x)
2. **Natural** (Ermil +30, Alena +20, speed 1.0x) ← **WINNER**
3. Energetic (Ermil +80, Alena +60, speed 1.1x, good emotion)
4. Professional (Ermil +50, Alena +30, speed 0.95x, neutral emotion)

### Final Configuration

**File:** `scripts/podcast_generator_yandex_v3.py`

```python
VOICES = {
    "host1": {"voice": "ermil", "emotion": "neutral", "pitch_shift": 30},
    "host2": {"voice": "alena", "emotion": "good", "pitch_shift": 20},
}
speed = 1.0  # Default
```

**Philosophy:** Minimal changes = maximum naturalness. Values close to natural human speech ranges for comfortable long-form listening.

**Denis's verdict:** "Натуральный диалог" — самый адекватный вариант.

### Alternative: Edge TTS (Free)

Also created `podcast_generator_edge.py` using Microsoft Edge TTS:
- **Voices:** ru-RU-DmitryNeural (male), ru-RU-SvetlanaNeural (female)
- **Pros:** 100% free, no API keys, no limits
- **Cons:** Less control (no Hz-level pitch shift), only 2 voices vs 6+ in Yandex
- **Use case:** Simple podcasts without budget

### Documentation

Updated `TOOLS.md` with:
- API v3 gRPC details
- TTS markup syntax (pauses, accents, phonemes)
- Final natural settings
- Comparison: API v1 → v3 → Edge TTS

### Key Learnings

1. **Pitch shift matters:** +30/+20 Hz sounds more natural than +70/+50 Hz
2. **Speed matters:** 1.0x better than 1.05x for podcasts
3. **Emotion control:** "good" for Alena, "neutral" for Ermil works well
4. **Natural pauses:** Let TTS handle pauses, don't force explicit sil<> tags
5. **Research helps:** Looking up WPM standards and frequency ranges led to better settings

✅ Final natural configuration applied
✅ Documentation updated
✅ Free alternative (Edge TTS) available as fallback

### Проблема tool_choice: "auto" (16:10-16:40)
Многие модели (GLM-4.6, GLM-4.7, GLM-4.7-Flash, MiniMax-M2, DeepSeek-OCR-2, Qwen3-Next-80B) крашатся с ошибкой:
`litellm.BadRequestError: "auto" tool choice requires --enable-auto-tool-choice and --tool-call-parser to be set`
Причина: vLLM backend не поддерживает `tool_choice: "auto"` без спец-флагов.

**Рабочие модели через litellm:** Qwen3-235B, gpt-oss-120b, Qwen3-Coder-480B, Qwen3-Coder-Next.

### Попытка native providers
Добавили native providers `zai` и `minimax` с `baseUrl` на LiteLLM endpoint — идея: обойти tool_choice.
- `zai/zai-org/GLM-4.6` (алиас `glm46`), `zai/zai-org/GLM-4.7-Flash` (алиас `glm47f`)
- `minimax/MiniMax-M2` (алиас `minimax`)

**Результат:** MiniMax-M2 через native provider выдаёт НОВУЮ ошибку:
`400 Tool 0 function has invalid 'parameters' schema: {} is not of type 'array'`
vLLM отвергает пустые `{}` в tool parameter schemas.

### Выводы
- В OpenClaw НЕТ compat-флага `supportsTools`/`disableTools` для отключения тулов per-model
- `suppressToolErrors: true` НЕ предотвращает замену текста ответа на ошибку в Telegram (баг)
- Workaround для exec ошибок: `|| true` в команде
- Нужно либо фиксить vLLM backend (--enable-auto-tool-choice), либо ждать OpenClaw compat flag
