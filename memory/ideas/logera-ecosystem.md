# Logera Ecosystem

_Зафиксировано: 2026-03-06_

## Концепция

Экосистема из трёх продуктов, связанных единым AI-слоем.

---

## LogeraLLM

**Что:** API-шлюз к собственным моделям с тарификацией по токенам  
**Для кого:** Разработчики, сервисы, компании  
**Монетизация:** Pay-per-token, иерархия ключей (org → project → service key)  
**Под капотом:** LiteLLM как routing + billing layer  
**Модели:** Qwen3-235B, GLM-4.7, Qwen3-Coder-480B и др. (собственная инфра)  
**Статус:** Инфра уже работает — ближайший к запуску продукт

---

## Logera.Space

**Что:** Корпоративная база знаний — документы организации, записи звонков, LLM-чат для поиска и создания документов  
**Для кого:** B2B, корпоративные клиенты  
**Монетизация:** Подписка per org  

---

## LogeraTask

**Что:** Таск-трекер ориентированный на календарь (не канбан)  
**Для кого:** B2B, команды  
**Монетизация:** Per seat или per org  
**Ключевая идея:** Задачи как временные блоки, AI-планирование, drag & drop в слоты  

---

## Почему экосистема сильнее чем три отдельных продукта

- Space знает документы → LLM имеет контекст организации
- Task знает задачи → AI планирует с учётом реальной загрузки
- LLM обслуживает оба продукта → единый AI-слой

Это сложно скопировать в отличие от просто "ещё одного LiteLLM proxy".

## Граф знаний — интеграция в workflow

После финализации графа:
1. **При ответе** — `query "<ключевое слово>"` если вопрос про людей/проекты/решения
2. **После записи в memory** — `python3 knowledge_graph.py build` (инкрементальный)
3. **В HEARTBEAT** — добавить шаг: build если есть изменённые файлы

## Reaction Handler (скилл)

Денис хочет чтобы я реагировал на реакции в Telegram:
- 👍 на мой ответ → запомнить что подход понравился (в memory)
- ❤️ → "лучший момент", добавить в дайджест
- 🤔 → предложить переформулировать / уточнить
- 🔥 → усилить этот стиль/подход в будущем

Реализация: hook на `message_reaction` event в Telegram → OpenClaw webhook → агент реагирует
