## 1. Цель и область применения

### 1.1. Цель продукта

Marginalia — мобильное приложение для чтения книг в форматах PDF, EPUB, FB2 и DJVU с возможностью выделения текста, создания заметок и семантического поиска по содержимому всей библиотеки. Приложение работает полностью офлайн: все данные, включая ML-модель для эмбеддингов, хранятся и обрабатываются на устройстве.

### 1.2. Целевая аудитория

Один пользователь — владелец устройства. Приложение не предполагает многопользовательского режима, авторизации, синхронизации или серверной части.

### 1.3. Ключевая ценность

- Единое место для хранения и чтения книг (PDF, EPUB, FB2, DJVU) на мобильном устройстве
- Семантический поиск «по смыслу» по всей библиотеке — не по точному совпадению слов, а по значению
- Приоритизация собственных выделений в результатах поиска — то, что пользователь отметил, находится первым
- Полная офлайн-работа без зависимости от интернета

### 1.4. Технический стек

| Компонент | Технология |
|-----------|------------|
| Фронтенд | SvelteKit (adapter-static) + shadcn-svelte |
| Мобильная обёртка | Capacitor (Android + iOS) |
| ORM | Drizzle ORM |
| База данных | Capacitor SQLite (@capawesome-team/capacitor-sqlite) |
| ML-модель | Transformers.js (multilingual-e5-small, dtype: q8, в бандле) |
| Парсинг книг | pdfjs-dist (PDF), epub.js (EPUB), DOMParser (FB2), djvu.js (DJVU) |

## 3. Функциональные требования

### 3.1. Экран «Библиотека» (FR-LIB)

#### FR-LIB-01: Отображение списка книг

**Описание:** Экран отображает вертикальный список всех добавленных книг.

**Элементы карточки книги:**
- Обложка (миниатюра первой страницы / обложка из метаданных книги)
- Название книги (из метаданных книги; если отсутствует — имя файла без расширения)
- Прогресс чтения (процент: `текущая_страница / общее_количество_страниц * 100`)
- Индикатор статуса индексации (иконка: ⏳ идёт / ✅ завершена / ⚠️ ошибка)

**Acceptance Criteria:**
- [ ] Книги отсортированы по дате последнего открытия (недавние — сверху)
- [ ] Обложка генерируется через BookParser (из первой страницы PDF, обложки EPUB/FB2) и кешируется как изображение в файловой системе
- [ ] Отображается корректный процент прогресса
- [ ] Тап по карточке открывает читалку на последней сохранённой странице

#### FR-LIB-02: Добавление книги

**Описание:** Пользователь может добавить книгу (PDF, EPUB, FB2 или DJVU) через системный файл-пикер.

**Поведение:**
1. Тап на FAB (+) → открывается системный файл-пикер с фильтром `application/pdf, application/epub+zip, application/x-fictionbook+xml, image/vnd.djvu`
2. Пользователь выбирает файл → файл копируется в внутреннее хранилище приложения
3. `BookParserFactory` определяет формат по расширению файла и выбирает нужный парсер
4. Показывается индикатор «Добавление книги...»
5. Извлекаются метаданные (название, количество страниц/глав)
6. Генерируется обложка (из первой страницы PDF, метаданных EPUB/FB2)
7. Создаётся запись в БД
8. Запускается фоновая индексация (парсинг текста → чанки → эмбеддинги)
9. Книга появляется в списке с индикатором индексации ⏳

**Acceptance Criteria:**
- [ ] Поддерживаются файлы PDF, EPUB, FB2 и DJVU
- [ ] Файл копируется во внутреннее хранилище (оригинал не модифицируется)
- [ ] Если файл повреждён или неподдерживаемого формата — показать ошибку «Не удалось открыть файл»
- [ ] Индексация не блокирует UI — книгу можно открыть и читать до завершения индексации
- [ ] При ошибке индексации — книга остаётся в библиотеке, иконка меняется на ⚠️, доступна кнопка «Повторить индексацию»

#### FR-LIB-03: Удаление книги

**Описание:** Долгое нажатие на карточку → контекстное меню с опцией «Удалить».

**Поведение:**
1. Лонг-пресс → появляется bottom sheet с опцией «Удалить книгу»
2. Подтверждение: диалог «Удалить книгу и все выделения? Это действие нельзя отменить.»
3. При подтверждении: удаляются файл PDF, обложка, все записи из БД (книга, чанки, эмбеддинги, выделения, заметки)

**Acceptance Criteria:**
- [ ] Требуется подтверждение через диалог
- [ ] Удаляются все связанные данные (каскадное удаление)
- [ ] Список обновляется немедленно

### 3.2. Экран «Читалка» (FR-READ)

#### FR-READ-01: Отображение страницы книги

**Описание:** Постраничный рендеринг книги через соответствующий BookParser.

**Поведение:**
- Отображается одна страница за раз
- **PDF:** рендеринг через canvas (pdfjs-dist `renderPage`) + текстовый слой поверх canvas
- **EPUB:** рендеринг через epub.js в iframe/div; «страница» — виртуальная (разбиение по главам или по N символов)
- **FB2:** рендеринг через кастомный парсер; «страница» — виртуальная (разбиение по section или по N символов)
- **DJVU:** рендеринг через djvu.js (canvas-based); фиксированные страницы; текстовый слой поверх canvas (если есть в документе)
- При открытии книги — переход на последнюю сохранённую страницу

**Acceptance Criteria:**
- [ ] Страница рендерится корректно для всех поддерживаемых форматов, текст читаем
- [ ] Масштаб по умолчанию — ширина страницы = ширина экрана
- [ ] Pinch-to-zoom поддерживается (масштабирование жестами)
- [ ] При открытии — переход к `lastReadPage` из БД
- [ ] EPUB и FB2: виртуальная пагинация работает консистентно (позиция сохраняется корректно)

#### FR-READ-02: Навигация по страницам

**Описание:** Перелистывание свайпом или тапом.

**Поведение:**
- Свайп влево → следующая страница
- Свайп вправо → предыдущая страница
- Тап по правой четверти экрана → следующая страница
- Тап по левой четверти экрана → предыдущая страница
- Тап по центру экрана → показать/скрыть тулбар и нижнюю панель

**Нижняя панель (при видимом тулбаре):**
- Слайдер прогресса (drag → переход к странице)
- Текст: «Стр. N из M»
- Поле ввода номера страницы (тап по «Стр. N из M» → input → Go)

**Acceptance Criteria:**
- [ ] Навигация работает свайпом и тапом
- [ ] На первой странице свайп вправо не делает ничего
- [ ] На последней странице свайп влево не делает ничего
- [ ] Слайдер корректно отражает и изменяет позицию
- [ ] Позиция (номер страницы) сохраняется в БД при каждом перелистывании

#### FR-READ-03: Выделение текста

**Описание:** Пользователь может выделить фрагмент текста на странице.

**Поведение:**
1. Лонг-пресс на слове → начало выделения
2. Drag маркеров → расширение/сужение выделения
3. При отпускании — появляется плавающее меню:
   - «Выделить» — сохранить выделение (жёлтый фон)
   - «Выделить + Заметка» — сохранить + открыть поле для заметки
4. Выделенный текст подсвечивается жёлтым фоном (полупрозрачный)
5. Тап на существующее выделение → меню: «Заметка» / «Удалить выделение»

**Acceptance Criteria:**
- [ ] Выделение работает по текстовому слою pdfjs
- [ ] Выделение сохраняется в БД с привязкой к книге, странице и позиции в тексте
- [ ] При повторном открытии страницы выделения отображаются
- [ ] Заметка — свободный текст, до 2000 символов
- [ ] Выделение нескольких фрагментов на одной странице поддерживается

#### FR-READ-04: Тулбар читалки

**Описание:** Верхний тулбар, показываемый по тапу в центр.

**Элементы:**
- Кнопка «Назад» (←) — вернуться в библиотеку
- Название книги (обрезается с многоточием)
- Кнопка «Поиск» (🔍) — переход к экрану поиска

### 3.3. Экран «Поиск» (FR-SEARCH)

#### FR-SEARCH-01: Ввод запроса и отображение результатов

**Описание:** Семантический поиск по смыслу по всей библиотеке.

**Поведение:**
1. Строка ввода запроса вверху экрана (autofocus при открытии)
2. Поиск запускается по нажатию кнопки «Искать» или Enter (не по мере ввода — вычисление эмбеддинга дорогое)
3. Запрос → вычисление эмбеддинга через Transformers.js → косинусное сходство со всеми чанками в БД → сортировка
4. Результаты разделены на две секции:
   - **«Мои выделения»** — чанки, которые пересекаются с выделениями пользователя (показываются первыми)
   - **«Из книг»** — остальные чанки
5. Каждый результат содержит:
   - Фрагмент текста (до 200 символов, с подсветкой ключевых слов если возможно)
   - Название книги
   - Номер страницы
   - Оценка релевантности (не показывается пользователю, используется для сортировки)

**Acceptance Criteria:**
- [ ] Поиск работает полностью офлайн
- [ ] Результаты выделений пользователя всегда выше обычных фрагментов
- [ ] Минимальный порог релевантности: cosine similarity ≥ 0.3 (ниже — не показывать)
- [ ] Максимум 50 результатов (25 выделений + 25 из книг)
- [ ] Время поиска: < 2 сек на библиотеку из 20 книг (см. NFR)

#### FR-SEARCH-02: Переход к результату

**Описание:** Тап на результат поиска открывает книгу на нужной странице.

**Acceptance Criteria:**
- [ ] Открывается экран читалки с нужной книгой на нужной странице
- [ ] Если это выделение — оно подсвечивается/мигает 2 секунды для привлечения внимания
- [ ] Кнопка «Назад» из читалки возвращает к результатам поиска (с сохранением запроса)

### 3.4. Экран «Цитаты» (FR-QUOTES)

#### FR-QUOTES-01: Список всех выделений

**Описание:** Все выделения пользователя из всех книг в хронологическом порядке (новые сверху).

**Элементы карточки выделения:**
- Текст выделения
- Заметка (если есть) — под текстом, курсивом, серым цветом
- Название книги
- Номер страницы
- Дата создания

**Acceptance Criteria:**
- [ ] Отображаются все выделения из всех книг
- [ ] Сортировка: по дате создания, новые сверху
- [ ] Пустое состояние: «Пока нет выделений. Откройте книгу и выделите интересный фрагмент»

#### FR-QUOTES-02: Фильтр по книге

**Описание:** Вверху — выпадающий список (select / dropdown) с вариантами: «Все книги» + список книг, в которых есть выделения.

**Acceptance Criteria:**
- [ ] По умолчанию: «Все книги»
- [ ] В списке только книги, у которых есть хотя бы одно выделение
- [ ] При выборе книги — список фильтруется мгновенно

#### FR-QUOTES-03: Удаление выделения

**Описание:** Свайп влево по карточке → кнопка «Удалить» (красная).

**Acceptance Criteria:**
- [ ] Удаление без дополнительного подтверждения (swipe-to-delete — достаточный жест)
- [ ] Связанная заметка удаляется вместе с выделением
- [ ] Выделение убирается со страницы книги

#### FR-QUOTES-04: Переход к месту в книге

**Описание:** Тап на карточку выделения → переход к книге и странице.

**Acceptance Criteria:**
- [ ] Открывается читалка на нужной странице нужной книги
- [ ] Выделение подсвечивается/мигает 2 секунды

## 4. Детальное описание экранов

### 4.1. Навигация приложения

Нижняя навигационная панель (tab bar) с тремя вкладками:
- 📚 **Библиотека** (главная)
- 🔍 **Поиск**
- 💬 **Цитаты**

Экран «Читалка» открывается поверх навигации (full-screen, без tab bar).

### 4.2. Экран «Библиотека»

#### Layout

```
┌─────────────────────────────┐
│  Marginalia            [⋮]  │  ← Header
├─────────────────────────────┤
│                             │
│  ┌─────┐  Название книги    │  ← Карточка
│  │     │  ▓▓▓▓▓░░░░ 54%    │
│  │ IMG │  ✅ Проиндексирована│
│  └─────┘                    │
│─────────────────────────────│
│  ┌─────┐  Другая книга     │
│  │     │  ▓░░░░░░░░ 12%    │
│  │ IMG │  ⏳ Индексация...  │
│  └─────┘                    │
│                             │
│                       [+]   │  ← FAB
├─────────────────────────────┤
│  📚      🔍      💬         │  ← Tab bar
└─────────────────────────────┘
```

#### Состояния

| Состояние | Описание |
|-----------|----------|
| **Пустое** | Центрированная иллюстрация + текст: «Библиотека пуста. Нажмите +, чтобы добавить первую книгу» |
| **Загрузка** | Skeleton-карточки (3 шт.) при первом запуске, пока БД инициализируется |
| **Заполненное** | Список карточек книг, отсортированных по дате последнего чтения |
| **Ошибка** | Toast-уведомление при ошибке операции (добавление, удаление) |
| **Индексация** | Карточка книги показывает прогресс-бар индексации и иконку ⏳ |

```typescript
// src/lib/db/schema.ts

import { sqliteTable, text, integer, real, blob } from 'drizzle-orm/sqlite-core';

export const books = sqliteTable('books', {
  id: text('id').primaryKey(),
  title: text('title').notNull(),
  filePath: text('file_path').notNull().unique(),
  format: text('format').notNull(), // 'pdf' | 'epub' | 'fb2' | 'djvu'
  coverPath: text('cover_path'),
  totalPages: integer('total_pages').notNull(),
  lastReadPage: integer('last_read_page').notNull().default(1),
  indexingStatus: text('indexing_status').notNull().default('pending'),
  indexingProgress: real('indexing_progress').default(0),
  fileSizeBytes: integer('file_size_bytes'),
  fileHash: text('file_hash'),
  lastOpenedAt: text('last_opened_at'),
  createdAt: text('created_at').notNull().default(sql`(datetime('now'))`),
  updatedAt: text('updated_at').notNull().default(sql`(datetime('now'))`),
});

export const chunks = sqliteTable('chunks', {
  id: text('id').primaryKey(),
  bookId: text('book_id').notNull().references(() => books.id, { onDelete: 'cascade' }),
  pageNumber: integer('page_number').notNull(),
  chunkIndex: integer('chunk_index').notNull(),
  text: text('text').notNull(),
  embedding: blob('embedding'),
  charOffsetStart: integer('char_offset_start'),
  charOffsetEnd: integer('char_offset_end'),
  createdAt: text('created_at').notNull().default(sql`(datetime('now'))`),
});

export const highlights = sqliteTable('highlights', {
  id: text('id').primaryKey(),
  bookId: text('book_id').notNull().references(() => books.id, { onDelete: 'cascade' }),
  pageNumber: integer('page_number').notNull(),
  text: text('text').notNull(),
  startOffset: integer('start_offset').notNull(),
  endOffset: integer('end_offset').notNull(),
  color: text('color').notNull().default('yellow'),
  note: text('note'),
  createdAt: text('created_at').notNull().default(sql`(datetime('now'))`),
  updatedAt: text('updated_at').notNull().default(sql`(datetime('now'))`),
});

export const appSettings = sqliteTable('app_settings', {
  key: text('key').primaryKey(),
  value: text('value').notNull(),
});
```

## 6. Нефункциональные требования

### 6.1. Поддерживаемые форматы

| Формат | MIME-тип | Библиотека | Пагинация | Изображения | Особенности |
|--------|----------|------------|-----------|-------------|-------------|
| **PDF** | `application/pdf` | pdfjs-dist | Фиксированные страницы | Да (рендеринг через canvas) | Основной формат; текстовый слой для выделений; скан-PDF без OCR не индексируются |
| **EPUB** | `application/epub+zip` | epub.js | Виртуальная (по главам или по N символов) | Да (HTML/CSS внутри ZIP) | Рефлоится под экран; epub.js рендерит в iframe/div; нет фиксированных страниц |
| **FB2** | `application/x-fictionbook+xml` | DOMParser (встроенный) | Виртуальная (по section или по N символов) | Только обложка | XML-формат, популярен в русскоязычном сегменте; структура body → section → p; без внешних зависимостей |
| **DJVU** | `image/vnd.djvu` | djvu.js | Фиксированные страницы | Да (рендеринг через djvu.js) | В основном сканы с текстовым слоем; извлечение текста зависит от наличия текстового слоя; рендеринг через djvu.js; open source библиотека (https://github.com/ArkoseLabs/djvujs) |

**Не поддерживаемые форматы:**

| Формат | Причина |
|--------|---------|
| MOBI / AZW | Проприетарные форматы Amazon; нет открытых JS-парсеров |

### 6.2. Производительность

| Метрика | Требование | Метод измерения |
|---------|-----------|-----------------|
| Время открытия приложения (cold start) | < 3 сек | От тапа по иконке до отображения списка книг |
| Время рендеринга страницы (PDF) | < 500 мс | От перелистывания до полного отображения |
| Время индексации одной книги (200 стр.) | < 5 мин | Фоновая задача, не блокирует UI |
| Время семантического поиска (20 книг) | < 2 сек | От нажатия «Искать» до отображения результатов |
| Вычисление одного эмбеддинга | < 200 мс | Один вызов Transformers.js inference |
| Загрузка ML-модели | < 3 сек | Первый вызов после запуска приложения (из бандла) |

### 6.3. Размер приложения

| Метрика | Требование |
|---------|-----------|
| Размер APK / IPA (без книг) | < 80 МБ |
| ML-модель (multilingual-e5-small q8) | ~33 МБ (включена в бандл) |
| Размер эмбеддинга одного чанка | 384 × 4 = 1536 байт (Float32, 384 dimensions) |
| Оценка БД на 20 книг (~4000 стр.) | ~60 МБ (эмбеддинги + текст чанков) |

### 6.4. Офлайн-работа

- Приложение **полностью работоспособно без интернет-соединения**
- Никакие функции не требуют сетевых запросов
- ML-модель включена в бандл приложения, не загружается из сети
- Все данные хранятся локально в SQLite

### 6.5. Совместимость

| Платформа | Минимальная версия | Примечания |
|-----------|-------------------|------------|
| Android | 8.0 (API 26) | Capacitor 5+ поддерживает |
| iOS | 14.0 | Capacitor 5+ поддерживает |

### 6.6. Потребление ресурсов

| Ресурс | Ограничение |
|--------|-------------|
| RAM в покое (список книг) | < 100 МБ |
| RAM при чтении | < 200 МБ |
| RAM при индексации | < 300 МБ |

### 6.7. Надёжность данных

- При крахе приложения во время индексации: при следующем запуске — обнаружить незавершённую индексацию (`status = in_progress`), возобновить с последнего проиндексированного чанка
- Копия PDF хранится во внутреннем хранилище приложения — защищена от удаления пользователем через файловый менеджер
- Миграции БД через Drizzle ORM: версионирование через `app_settings.db_version`

## 7. Сценарии использования

### 7.1. UC-01: Первый запуск и добавление книги

**Предусловия:** Приложение установлено, библиотека пуста.

### 8.2. Модуль: Book Parser (абстракция)

**Ответственность:** Единый интерфейс для извлечения текста, рендеринга страниц и получения метаданных из книг разных форматов (PDF, EPUB, FB2, DJVU).

#### 8.2.1. Интерфейс BookParser


#### 8.2.2. Фабрика BookParserFactory

```typescript
// src/lib/modules/book-parser/factory.ts

class BookParserFactory {
  private static parsers: BookParser[] = [
    new PdfBookParser(),
    new EpubBookParser(),
    new Fb2BookParser(),
    new DjvuBookParser(),
  ];

  /**
   * Выбирает парсер по расширению файла.
   * @throws Error если формат не поддерживается
   */
  static getParser(filePath: string): BookParser {
    const ext = filePath.split('.').pop()?.toLowerCase() ?? '';
    const mimeType = this.getMimeType(ext);
    const parser = this.parsers.find(p => p.canParse(mimeType, ext));
    if (!parser) throw new Error(`Формат .${ext} не поддерживается`);
    return parser;
  }

  private static getMimeType(ext: string): string {
    const map: Record<string, string> = {
      pdf: 'application/pdf',
      epub: 'application/epub+zip',
      fb2: 'application/x-fictionbook+xml',
      djvu: 'image/vnd.djvu',
    };
    return map[ext] ?? 'application/octet-stream';
  }
}
```

### 8.3. Модуль: Indexer

**Ответственность:** Извлечение текста из книги (через BookParser), разбиение на чанки, вычисление эмбеддингов, сохранение в БД.

**Интерфейс:**

```typescript
// src/lib/modules/indexer.ts

interface Indexer {
  /**
   * Запускает полную индексацию книги.
   * Работает в фоне, не блокирует UI.
   * @param bookId — ID книги в БД
   * @param onProgress — callback для обновления прогресса (0.0–1.0)
   */
  indexBook(bookId: string, onProgress?: (progress: number) => void): Promise<IndexResult>;

  /**
   * Возобновляет прерванную индексацию.
   * Определяет последний проиндексированный чанк и продолжает.
   */
  resumeIndexing(bookId: string, onProgress?: (progress: number) => void): Promise<IndexResult>;

  /**
   * Удаляет все чанки и эмбеддинги книги (для переиндексации).
   */
  clearIndex(bookId: string): Promise<void>;

  /**
   * Отменяет текущую индексацию.
   */
  cancel(): void;
}

interface IndexResult {
  bookId: string;
  totalChunks: number;
  totalPages: number;
  skippedPages: number; // страницы без извлекаемого текста
  durationMs: number;
  status: 'completed' | 'error' | 'cancelled';
  error?: string;
}
```

**Алгоритм разбиения на чанки:**
1. Для каждой страницы: извлечь текст через BookParser (выбранный BookParserFactory)
2. Разбить текст на абзацы (разделитель: двойной перенос строки `\n\n`)
3. Если абзац > 512 символов — разбить по предложениям, собирать чанки до ~400 символов
4. Если абзац < 50 символов — объединить с соседним
5. Для каждого чанка: вычислить эмбеддинг через EmbeddingsModule
6. Сохранить чанк + эмбеддинг в таблицу `chunks`
7. Обновить `books.indexing_progress` после каждой страницы

**Зависимости:** BookParserFactory, EmbeddingsModule, DB Layer

### 8.4. Модуль: Embeddings

**Ответственность:** Инициализация ML-модели, вычисление эмбеддингов текста.

**Интерфейс:**

```typescript
// src/lib/modules/embeddings.ts

interface EmbeddingsModule {
  /**
   * Инициализация модели (вызывается один раз при запуске).
```

- Размерность: 384
- Prefix для E5: `"query: "` для поисковых запросов, `"passage: "` для текстов книг
- Runtime: Transformers.js (ONNX Runtime Web / WASM)

**Зависимости:** `@xenova/transformers` (или `@huggingface/transformers`)

### 8.5. Модуль: Search Engine

**Ответственность:** Семантический поиск по чанкам с приоритизацией выделений.

**Интерфейс:**

```typescript
// src/lib/modules/search-engine.ts

interface SearchEngine {
  /**
   * Выполняет семантический поиск.
   * @param query — поисковый запрос пользователя
   * @param options — параметры поиска
   * @returns Результаты, разделённые на выделения и обычные
   */
  search(query: string, options?: SearchOptions): Promise<SearchResults>;
}

interface SearchOptions {
  /** Минимальный cosine similarity (default: 0.3) */
  minScore?: number;
  /** Максимум результатов выделений (default: 25) */
  maxHighlights?: number;
  /** Максимум результатов из книг (default: 25) */
  maxChunks?: number;
  /** Фильтр по конкретной книге */
  bookId?: string;
}

interface SearchResults {
  highlights: SearchResult[]; // Выделения пользователя (приоритет)
  chunks: SearchResult[];     // Обычные фрагменты из книг
  queryTimeMs: number;        // Время выполнения
}

interface SearchResult {
  chunkId: string;
  bookId: string;
  bookTitle: string;
  pageNumber: number;
  text: string;               // Текст чанка (до 200 символов)
  score: number;              // Cosine similarity (0–1)
  highlightId?: string;       // ID выделения (если это выделение)
  note?: string;              // Заметка к выделению (если есть)
}
```

**Алгоритм поиска:**
1. Вычислить эмбеддинг запроса: `embed(query, 'query')`
2. Загрузить все эмбеддинги из `chunks` (SELECT id, book_id, page_number, text, embedding FROM chunks)
3. Для каждого чанка: вычислить cosine similarity с запросом
4. Отфильтровать по порогу (≥ 0.3)
5. Загрузить все `highlights`
6. Для каждого результата: проверить, пересекается ли чанк с каким-либо highlight (по book_id + page_number + смещения)
7. Разделить результаты на две группы: с highlight и без
8. Сортировать каждую группу по score (desc)
9. Ограничить количество

**Оптимизация для больших библиотек:**
- Эмбеддинги можно кешировать в памяти после первого поиска (ленивая загрузка)
- При >10000 чанков: рассмотреть HNSW-индекс (но для MVP — brute force cosine similarity достаточно)

**Зависимости:** EmbeddingsModule, DB Layer

### 8.9. Взаимодействие модулей (sequence)

**Добавление книги:**
```
User → BookService.addBook(uri)
  → Filesystem.copy(uri, internalPath)
  → BookParserFactory.getParser(internalPath) → parser
  → parser.getMetadata(internalPath)
  → parser.generateCover(internalPath, maxWidth)
  → DbLayer.insertBook(metadata)
  → Indexer.indexBook(bookId)
    → parser.extractText(internalPath, page) [для каждой страницы]
    → EmbeddingsModule.embedBatch(chunks) [batch по странице]
    → DbLayer.insertChunks(chunksWithEmbeddings)
    → DbLayer.updateBook(bookId, { indexingProgress })
  → DbLayer.updateBook(bookId, { indexingStatus: 'completed' })
```

**Поиск:**
```
User → SearchEngine.search(query)
  → EmbeddingsModule.embed(query, 'query')
  → DbLayer.getAllChunksWithEmbeddings()
  → cosineSimilarity(queryEmbedding, chunkEmbeddings) [для каждого чанка]
  → DbLayer.getHighlights()
  → matchChunksWithHighlights(results, highlights)
  → sort + filter + limit
  → return SearchResults
```

### 9.1. Ограничения

| # | Ограничение | Описание |
|---|------------|----------|
| 1 | **Четыре формата: PDF, EPUB, FB2, DJVU** | Приложение поддерживает PDF, EPUB, FB2 и DJVU. MOBI/AZW не поддерживаются (проприетарные форматы Amazon, нет открытых JS-парсеров). |
| 2 | **Только текстовые PDF и DJVU** | PDF- и DJVU-файлы со сканированными изображениями (без текстового слоя) не индексируются. OCR не входит в MVP. Книгу можно открыть и читать, но поиск по ней не работает. DJVU без текстового слоя (чистые сканы) — аналогичное ограничение: рендеринг доступен, индексация и поиск невозможны. |
| 2a | **FB2 без изображений** | В FB2-книгах поддерживается только текст и обложка. Встроенные изображения на страницах не отображаются. |
| 3 | **Один пользователь** | Нет авторизации, нет мультиюзера. Все данные принадлежат одному пользователю. |
| 4 | **Нет синхронизации** | Данные хранятся только на устройстве. Нет облачного бэкапа, нет синхронизации между устройствами. |
| 5 | **Brute-force поиск** | Семантический поиск использует линейное сравнение со всеми эмбеддингами (O(n)). Для библиотек >50 книг может потребоваться оптимизация (ANN-индекс). |
| 6 | **Размер модели** | ML-модель (~33 МБ) включена в бандл, что увеличивает размер APK. Это сознательный trade-off ради офлайн-работы. |
| 7 | **Индексация при добавлении** | Индексация запускается немедленно при добавлении книги. Нет возможности «отложить» индексацию. При большой книге (>500 стр.) может занять значительное время. |
| 8 | **Язык модели** | multilingual-e5-small поддерживает ~100 языков, но качество поиска может варьироваться. Лучше всего работает с английским, русским, китайским, немецким, французским. |

### 9.2. Допущения

| # | Допущение | Обоснование |
|---|----------|-------------|
| 1 | Устройство имеет достаточно свободной памяти для хранения PDF-файлов и БД | Пользователь управляет библиотекой сам |
| 2 | PDF-файлы имеют текстовый слой (не сканы); DJVU-файлы желательно с текстовым слоем; EPUB и FB2 — валидные файлы | Целевые книги — электронные издания; DJVU-сканы без текстового слоя открываются, но не индексируются |
| 3 | Transformers.js стабильно работает в WebView на целевых платформах | Подтверждено сообществом для Capacitor + Android/iOS WebView |
| 4 | Capacitor SQLite поддерживает BLOB-поля для хранения эмбеддингов | Стандартная возможность SQLite, поддержана плагином |
| 5 | Размер библиотеки пользователя — до 50 книг | Оптимизация brute-force поиска рассчитана на эту величину |
| 6 | pdfjs-dist, epub.js и djvu.js корректно работают в Capacitor WebView | Широко используемые библиотеки, совместимость подтверждена сообществом; djvu.js — open source, работает в браузере без сервера |
| 7 | Пользователь добавляет книги из файловой системы устройства | Нет импорта из облачных хранилищ, URL, или других приложений |

### 9.3. Риски

| # | Риск | Вероятность | Влияние | Митигация |
|---|------|-------------|---------|-----------|
| 1 | Transformers.js медленно работает на слабых устройствах | Средняя | Высокое | Профилировать на Android 8 устройстве; если > 500 мс на эмбеддинг — рассмотреть smaller модель или WASM SIMD |
| 2 | pdfjs рендерит некорректно сложные PDF (формулы, таблицы) | Средняя | Среднее | Рендеринг для чтения; индексация текста может потерять форматирование — допустимо |
| 2a | epub.js некорректно рендерит сложные EPUB (с CSS-анимациями, SVG) | Средняя | Среднее | Поддерживаем стандартные EPUB; сложная вёрстка может отображаться упрощённо |
| 2b | Виртуальная пагинация EPUB/FB2 нестабильна при изменении размера экрана | Средняя | Среднее | Пересчитывать позицию при resize; сохранять позицию по процентам текста, а не по номеру страницы |
| 3 | Большие PDF (>1000 стр.) вызывают OOM при индексации | Низкая | Высокое | Постраничная обработка, batch эмбеддингов по 1 странице, GC после каждой страницы |
| 4 | BLOB-эмбеддинги в SQLite медленно читаются при большой БД | Низкая | Среднее | Ленивая загрузка; кеш в памяти; при необходимости — вынести эмбеддинги в отдельный файл |
| 5 | Capacitor SQLite plugin несовместим с Drizzle ORM | Низкая | Высокое | Проверить совместимость на этапе прототипирования; fallback — raw SQL через plugin API |

## Приложение A: Формат хранения эмбеддингов

Каждый эмбеддинг — `Float32Array` длиной 384 элемента.

**Сериализация для SQLite BLOB:**
```typescript
// Запись
const blob = new Uint8Array(embedding.buffer);

// Чтение
const embedding = new Float32Array(blob.buffer);
```

**Размер одного эмбеддинга:** 384 × 4 = 1536 байт

**Оценка для средней книги (200 стр., ~10 чанков/стр.):**
- 2000 чанков × 1536 байт = ~3 МБ (только эмбеддинги)
- + текст чанков: ~500 КБ
- Итого на книгу: ~3.5 МБ

## Приложение B: Cosine Similarity

```typescript
function cosineSimilarity(a: Float32Array, b: Float32Array): number {
  let dotProduct = 0;
  let normA = 0;
  let normB = 0;
  for (let i = 0; i < a.length; i++) {
    dotProduct += a[i] * b[i];
    normA += a[i] * a[i];
    normB += b[i] * b[i];
  }
  return dotProduct / (Math.sqrt(normA) * Math.sqrt(normB));
}
```
