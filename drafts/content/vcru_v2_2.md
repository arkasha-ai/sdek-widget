# Почему ЮKassa не для стартапов

*Реальное сравнение платёжных систем для тех, кто запускает SaaS в России*

---

Подключить оплату — задача на день. Выбрал платёжку, подключил, готово. Так я думал. У нас ушла неделя. Делюсь разбором, чтобы вы эту неделю не тратили.

SellerShot — SaaS для селлеров маркетплейсов. Подписочная модель плюс разовые покупки пакетов генераций. ИП на старте. Клиенты — физлица (селлеры-одиночки) и мелкий бизнес (ИП/ООО).

Требования простые: карты (МИР обязательно), рекуррентные платежи для подписок, быстрое подключение без бюрократии на месяц, вменяемая комиссия.

## ЮKassa: почему нет

Первое, что приходит в голову. Крупнейший агрегатор, все знают. Мы тоже начали с него.

Подключение — нужен договор, для договора ИП или ООО. Самозанятым — мимо. Верификация — несколько дней. Заполнение форм — отдельный вид боли. Для стартапа, которому нужно «принять первый платёж сегодня» — слишком медленно.

Комиссия — от 3.5%. Для SaaS с невысоким средним чеком — каждый процент ощутим. Рекуррентные платежи — отдельная сертификация, ещё время.

Интеграция — SDK есть, документация адекватная. Но для простого «начать принимать деньги» — слишком много шагов.

ЮKassa — для зрелого бизнеса с оборотом и юрлицом. Для стартапа, запускающегося за выходные — оверкилл.

## Альтернативы

**Prodamus** — позиционируется для инфобизнеса, но подходит для любого SaaS. Быстрое подключение (часы, не дни), работает с самозанятыми, встроенные рекуррентные платежи, неплохое API. Минусы: комиссия повыше прямого эквайринга, интерфейс админки — прямиком из 2015 года, поддержка не всегда быстрая.

**Antilopay** — заточен под digital-продукты. Быстрая интеграция, работает с самозанятыми, адекватная документация. Минус: менее обкатан рынком, меньше информации в открытых источниках.

## Т-Банк: наш выбор

Не потому что идеален — для нашего кейса оптимален.

Подключение быстрое. ИП — пару дней, без излишней бюрократии. Комиссия ниже агрегаторов — прямой эквайринг, разница ощутима при растущих оборотах. Рекуррентные платежи из коробки. API документирован, SDK есть, интеграция — несколько часов для нашего стека на Node.js.

Поддержка отвечает быстро. Для стартапа критично — ты не можешь ждать три дня, когда клиент не может оплатить.

Михаил смотрел с бизнес-стороны. Три его критерия:

«Сколько клиент ждёт оплату?» — у Т-Банка секунды. Для SaaS, где клиент хочет начать сразу — критично. «Что увидит на странице оплаты?» — знакомый бренд, доверие. Для малоизвестного стартапа доверие к платёжной странице важнее, чем кажется. «А если возврат?» — через API, автоматически. Не нужно звонить и просить вернуть вручную.

Бонус: Т-Банк — ещё и расчётный счёт. Приём, вывод, бухгалтерия — всё в одном месте. Для маленькой команды из двух человек это упрощает жизнь значительно — одна панель вместо трёх.

## Интеграция на практике

Мы подключились за два дня. Первый день — регистрация, верификация, получение ключей. Второй — интеграция в бэкенд. Написали обёртку над API, настроили webhook для callback'ов, протестировали все сценарии на тестовых картах. Рекуррентные платежи заработали сразу — не нужно было проходить отдельную сертификацию.

Единственный момент, который занял время — настройка webhook'ов для уведомлений об успешных и неуспешных платежах. Документация была, но пришлось поэкспериментировать с форматом подписи.

## Практические советы

Не тратьте неделю на выбор. Т-Банк или Prodamus — подключитесь за день, начните принимать деньги. Оптимизировать комиссию будете, когда появится оборот.

Самозанятым — Prodamus или Antilopay. ИП — Т-Банк. ООО с оборотом — можно ЮKassa, но Т-Банк скорее всего проще.

Рекуррентные платежи проверяйте ДО подключения — не все тарифы их поддерживают. Это неприятный сюрприз, когда уже интегрировался.

Тестовый режим — обязательно. Не подключайте прод, пока не прогнали все сценарии на тестовых картах: успешная оплата, отказ, возврат, повторная попытка. Мы нашли два бага в своём коде именно на тестовых сценариях — до прода они не дошли.

Главное правило: лучше начать принимать деньги сегодня с «неидеальной» платёжкой, чем выбирать идеальную ещё месяц. Оптимизировать будете, когда появится оборот.
