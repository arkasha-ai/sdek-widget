## Оптимизация GLM-4.7

### Проблема
Модель путала контекст и выдавала grep/find результаты вместо выполнения задачи.

### Решение
Настройка параметров в LiteLLM Admin UI:

```json
{
  "temperature": 1.0,
  "top_p": 0.95,
  "max_tokens": 16384,
  "chat_template_kwargs": {
    "enable_thinking": true,
    "clear_thinking": false
  }
}
```

### Результат
- **Быстрее Qwen** в 1.8x (24 сек vs 44 сек)
- Качественный результат с первого раза
- Оптимальная модель для subagent задач

## Текущие проблемы

### Reasoning mode GLM-4.7
**Симптом:** `503 APIConnectionError: Hosted_vllmException - 'id'`

**Причина:** В LiteLLM БД две модели GLM-4.7:
1. `GLM-4.7` (hosted_vllm, без api_base) — ❌ ломается
2. `zai-org/GLM-4.7` (openai, с api_base) — ✅ работает

**Статус:** ⏳ Ждёт исправления от Дениса
