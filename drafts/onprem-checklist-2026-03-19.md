# On-Premise Production Checklist

**Дата:** 19 марта 2026 г.
**Контекст:** Подготовка 4 AI-продуктов к production-деплою в закрытой инфраструктуре (фарма, высокая конфиденциальность, air-gapped допустимо).

---

## 1. SyncVoice

### Докеризация
- [ ] Все компоненты в Docker-контейнерах (STT, translation, TTS, API gateway)
- [ ] Docker Compose / Helm chart для оркестрации
- [ ] GPU passthrough настроен (nvidia-container-toolkit)
- [ ] Health-check endpoints в каждом контейнере
- [ ] Все образы собраны и протестированы в offline-режиме (docker save/load)

### Замена облачных зависимостей
- [ ] STT: Whisper large-v3 — веса скачаны, упакованы в образ или volume
- [ ] Перевод: NLLB / Madlad-400 — локальная модель вместо API
- [ ] TTS: Coqui XTTS / VITS — модели для 4 языков (RU/EN/HI/ZH) загружены локально
- [ ] Никаких внешних API-вызовов — проверить сетевым сканом

### Документация
- [ ] README: системные требования (GPU VRAM ≥24GB, RAM, диск)
- [ ] Пошаговая инструкция установки (от docker load до первого звонка)
- [ ] Конфигурация: env-файл с описанием всех переменных
- [ ] Troubleshooting: типичные ошибки и решения

### Мониторинг / логирование
- [ ] Structured logging (JSON) во всех сервисах
- [ ] Метрики: latency STT/TTS/translation, количество сессий, ошибки
- [ ] Prometheus endpoint или совместимый формат
- [ ] Интеграция с Grafana (дашборд поставляется)
- [ ] Алерты: latency >3 сек, OOM, GPU utilization >95%

### Бэкап
- [ ] Stateless-архитектура — бэкапить только конфиги и логи
- [ ] Скрипт бэкапа конфигурации (cron-ready)
- [ ] Документация по восстановлению после сбоя

### Сетевая изоляция и безопасность
- [ ] Работает в изолированном VLAN, без доступа в интернет
- [ ] WebSocket API доступен только из внутренней сети
- [ ] TLS для всех соединений (самоподписанный сертификат допустим)
- [ ] Аутентификация API (token/JWT)
- [ ] Аудит-лог подключений

## 2. Logera

### Докеризация
- [ ] Docker Compose: SvelteKit, FastAPI, PostgreSQL, MinIO, Whisper worker, LLM worker, pgvector
- [ ] Все сервисы с health-check
- [ ] Volume mapping для данных (PostgreSQL, MinIO, модели)
- [ ] Образы собраны и протестированы offline

### Замена облачных зависимостей
- [ ] LLM для RAG: self-hosted (llama.cpp / vLLM + модель, например Qwen2.5 / Mistral)
- [ ] Embedding-модель: локальная (e5-large / bge-m3) — без OpenAI API
- [ ] Whisper: локальный, веса в volume
- [ ] MinIO вместо S3 — уже в стеке ✓
- [ ] pgvector вместо Pinecone/Qdrant cloud — уже в стеке ✓
- [ ] Проверить все pip/npm зависимости — нет ли runtime-вызовов к облаку

### Документация
- [ ] Системные требования: GPU (для LLM + Whisper), RAM ≥32GB, диск ≥500GB
- [ ] Инструкция: установка, первичная настройка, загрузка первых документов
- [ ] Админ-гайд: управление пользователями, настройка индексации
- [ ] API-документация (Swagger/OpenAPI)

### Мониторинг / логирование
- [ ] Централизованные логи (stdout → Loki / ELK стек клиента)
- [ ] Метрики: количество документов, поисковых запросов, время ответа RAG
- [ ] Дашборд Grafana
- [ ] Алерты: диск заполнен >80%, PostgreSQL connections, LLM timeout

### Бэкап
- [ ] PostgreSQL: pg_dump по расписанию (ежедневно)
- [ ] MinIO: rsync / mc mirror файлового хранилища
- [ ] Скрипт полного бэкапа (БД + файлы + конфиги)
- [ ] Тест восстановления из бэкапа — провести до сдачи
- [ ] Документация по disaster recovery

### Сетевая изоляция и безопасность
- [ ] Все порты закрыты кроме UI (443) и API
- [ ] Аутентификация пользователей (SSO/LDAP интеграция или встроенная)
- [ ] Ролевая модель: админ / пользователь / viewer
- [ ] Шифрование данных at rest (PostgreSQL TDE или LUKS)
- [ ] Шифрование в transit (TLS)
- [ ] Аудит-лог: кто загружал, кто искал, какие документы открывал

## 3. Sales Coach

### Докеризация
- [ ] Docker Compose: STT worker, LLM worker, WebSocket server, API gateway, CRM connector
- [ ] GPU passthrough для STT и LLM
- [ ] Health-check для каждого сервиса
- [ ] Образы offline-ready

### Замена облачных зависимостей
- [ ] STT: Whisper streaming (faster-whisper) — локально, GPU
- [ ] LLM: self-hosted (vLLM / llama.cpp), модель с хорошим русским (Qwen2.5 / Vikhr)
- [ ] Нет зависимости от внешних CRM API — коннектор к локальной CRM клиента
- [ ] Проверить: нет ли telemetry / analytics вызовов наружу

### Документация
- [ ] Системные требования: GPU VRAM ≥24GB (STT + LLM), RAM ≥32GB
- [ ] Инструкция установки и подключения к CRM
- [ ] Гайд для менеджеров: как подключиться, как использовать подсказки
- [ ] Настройка скриптов продаж и промптов

### Мониторинг / логирование
- [ ] Метрики: latency подсказок, количество активных сессий, качество распознавания
- [ ] Логирование без записи содержания звонков (privacy by design)
- [ ] Prometheus + Grafana дашборд
- [ ] Алерты: latency подсказок >5 сек, падение STT worker

### Бэкап
- [ ] Бэкап конфигурации и промптов/скриптов
- [ ] Бэкап аналитических данных (если хранятся)
- [ ] CRM-коннектор: конфигурация отдельно

### Сетевая изоляция и безопасность
- [ ] Аудио-поток НЕ записывается и НЕ сохраняется (если не согласовано иное)
- [ ] WebSocket только из внутренней сети
- [ ] Аутентификация менеджеров (привязка к CRM-аккаунту)
- [ ] TLS на всех соединениях
- [ ] Логи без PII (персональных данных клиентов)

## 4. Персональный AI-агент («Клон Аркаши»)

### Докеризация
- [ ] Docker-контейнер на каждого агента (или один с multi-tenant)
- [ ] LLM-сервер отдельным контейнером (shared между агентами)
- [ ] Векторная БД (pgvector / Qdrant) — отдельный контейнер
- [ ] Telegram Bot — контейнер с bot polling (без webhook если air-gapped)
- [ ] Docker Compose для полного стека

### Замена облачных зависимостей
- [ ] LLM: self-hosted (vLLM + Qwen2.5 / Mistral / LLaMA)
- [ ] Whisper: локальный (для голосовых сообщений)
- [ ] TTS: локальный (если нужен голосовой ответ)
- [ ] Векторная память: локальный pgvector / Qdrant (не cloud)
- [ ] Telegram Bot API: проксирование через внутренний сервер ИЛИ self-hosted Telegram Bot API server
- [ ] ⚠️ **Важно:** Telegram Bot API требует исходящее соединение — обсудить с клиентом: внутренний Telegram-сервер / Matrix / другой мессенджер / веб-интерфейс

### Документация
- [ ] Системные требования: GPU для LLM, RAM ≥16GB на агента
- [ ] Инструкция: создание бота, настройка, первый запуск
- [ ] Гайд по кастомизации: добавление инструментов, настройка промптов, интеграции
- [ ] Инструкция для пользователей (сотрудников)

### Мониторинг / логирование
- [ ] Метрики: количество сообщений, время ответа, использование инструментов
- [ ] Логирование без содержания переписки (или с шифрованием)
- [ ] Health-check бота (ping/pong)
- [ ] Алерт при падении бота >5 мин

### Бэкап
- [ ] Векторная память агента — бэкап ежедневно
- [ ] Конфигурация и промпты — version control
- [ ] PostgreSQL (если используется для state) — pg_dump
- [ ] Скрипт полного бэкапа всех агентов

### Сетевая изоляция и безопасность
- [ ] Каждый агент изолирован (свой контейнер, свои данные)
- [ ] Агент НЕ имеет доступа к данным других агентов
- [ ] Шифрование памяти at rest
- [ ] Аутентификация: привязка к Telegram user ID
- [ ] Аудит-лог использования инструментов
- [ ] Rate limiting на API

## Общие требования к инфраструктуре клиента

### Серверы
- [ ] GPU-сервер: минимум 2× NVIDIA A100/H100 (80GB VRAM) или эквивалент
- [ ] CPU-серверы для вспомогательных сервисов
- [ ] RAM: ≥128GB суммарно
- [ ] Диск: ≥2TB SSD (NVMe предпочтительно)

### Сеть
- [ ] Изолированный VLAN для AI-сервисов
- [ ] Firewall: whitelist-only для входящих подключений
- [ ] DNS: внутренний DNS для сервисов
- [ ] NTP: синхронизация времени (важно для логов)

### Общий мониторинг
- [ ] Prometheus + Grafana (или стек клиента)
- [ ] Централизованный сбор логов
- [ ] Алертинг (email / мессенджер клиента)

### Общий бэкап
- [ ] Стратегия: ежедневный инкрементальный + еженедельный полный
- [ ] Хранение: минимум 30 дней
- [ ] Тест восстановления: перед вводом в production
